## 3. Как здесь принято работать

Правила из `CLAUDE.md` обязательны. Сверх них — договорённости с Никитой и то, чему научила эта сессия.

- **Одна задача — одна ветка и один PR** (для R01 — один PR с несколькими коммитами по шагам). Имена веток: `fix/S02-safe-clean`, `feat/N02-md5-identify`. ID задачи — в заголовке коммита.
- **Сначала тест, который падает, потом правка.** В отчёте указывай, сколько тестов падало до исправления.
- **После каждой задачи — отчёт Никите:** файлы; что и почему; побочные эффекты; какие команды запускал и что вышло на самом деле; что проверить не удалось.
- **Проверки ставь перед коммитом жёстко** (`set -e` или `&&` без `;`). В этой сессии коммит один раз ушёл с хвостовым пробелом, потому что проверка стояла в цепочке через `;`.
- **`docs/HANDOFF.md` обновляй в том же PR**, что и задачу.
- **Новые зависимости — только с согласия.** Разрешено: ruff в CI (только проверка). Не разрешено пока: mypy, PyInstaller, pytest, pywebview.
- **Отчёты и README — на русском.** Сообщения коммитов в репозитории на английском.
- В подписи коммитов не указывай название модели.

### Тесты не должны трогать файлы пользователя

Это самое частое место ошибок. Константы путей в `nexus_links.py` указывают на папку проекта, где у Никиты лежат настоящие файлы. При вызове перечисленных функций в тестах подменяй:

| Что вызываешь | Что подменять |
|---|---|
| `render_dashboard`, `load_blacklist` | `nexus_links.load_custom_blacklist` → `{}` |
| `cmd_scan` | `nexus_links.HASH_CACHE_PATH` → путь во временной папке; `load_settings`, `load_blacklist`, `run_ai` |
| `run_ai` | `nexus_links.load_ai_cache` (иначе читается `ai_cache.json`) |
| `apply_ai_budgets` с ключом | `nexus_links.remaining_daily_requests` (иначе читается `openrouter_usage.json` и рядом создаётся `.lock`) |
| `load_settings` | передавай `config=<временный файл>`; подменяй `find_cyberpunk_install`; добавляй `addCleanup(nexus_links.set_max_mod_id)` |
| всё, что меняет лимиты | `addCleanup(openrouter_limits.configure_budgets)` и `patch.object(openrouter_limits, "_requests_this_process", 0)` |

Ловушка: аргумент по умолчанию вида `path: Path = USAGE_PATH` вычисляется при определении функции, поэтому `patch("модуль.USAGE_PATH")` на него **не действует** — передавай путь явно или подменяй саму функцию. После прогона тестов проверь, что в папке проекта не появилось `mod_cache.json`, `openrouter_usage.json*`, `*_cache.json`.

### Проверка дашборда в браузере

JS в `unittest` исполняется только частично: блок между `// <pure-logic>` и `// </pure-logic>` в `dashboard_template.html` запускает `tests/test_dashboard_js.py` под Node.js (без Node тесты пропускаются). Всё, что работает с DOM, в репозитории не покрыто.

В этой сессии DOM проверялся скриптами Playwright вне репозитория (они не сохранены). Схема, если понадобится повторить: скрипт на Python создаёт во временной папке архивы, вызывает `_scan_archive_roots` → `_prepare_scan_archives` → `build_rows` → `render_dashboard`, пишет HTML и поднимает `server.make_handler(..., port=<порт>)` на `127.0.0.1`; Playwright открывает страницу с `reducedMotion: 'reduce'` (иначе мешает заставка) и жмёт кнопки. Порт в `make_handler` обязан совпадать с портом сервера, иначе запросы получат `403 forbidden_origin`.

| `dashboard_template.html` | CSS и JS дашборда; плейсхолдеры `@@ИМЯ@@` подставляет `render_dashboard` |
| `start.bat` | Первый запуск, один вызов `scan --ai-until-budget`, запуск сервера |

Появилось на этапе 1 и стоит переиспользовать, а не писать заново:

- **Запись файлов:** `json_files.atomic_write_json(path, data, indent=2)` — единственный способ писать JSON (за этим следит тест).
- **Настройки:** `load_settings(args)` → `Settings`; бросает `ConfigError`. `configured_max_mod_id(cfg)`, `set_max_mod_id()`. `resolve_openrouter(settings, args) → (key, models)`. `apply_ai_budgets(settings, args, announce)`.
- **Очистка:** `iter_clean_checks(entries, downloads, quarantine)` → пары `(запись, причина пропуска | None)`; `_apply_clean_plan(plan, quarantine, mode, outcome)` с `CleanOutcome`; `verify_entry` всегда считает SHA-256 по самому файлу.
- **Хеши:** `file_digests(path) → (sha256, md5)` за одно чтение; `HashCache.get/put/prune/save`. MD5 уже лежит в кэше и ждёт N02.
- **Сервер:** `make_handler(downloads, dashboard, blacklist, config, port, quarantine, reveal_roots)`; `inside_roots(path, roots)`; `insert_token(page, token)`.
- **Подписи:** `source_label(name, folder)`, `duplicate_banner_text(...)`.
- **JS:** чистые функции `fmtSize`, `baseName`, `pickSelected`, `buildSelection`, `serverMessage` — в блоке `<pure-logic>`; новые ответы сервера добавляй в `serverMessage`, иначе упадёт тест.

## 7. Что не проверено и чего стоит ждать

На настоящей Windows-машине не запускалось ничего, кроме тестов в CI. Никите стоит проверить руками:

- `start.bat` целиком, включая ветку «нет `python`, есть `py -3`».
- Кнопку «В папке»: `explorer /select,"путь"` на пути с пробелами и кириллицей.
- Перенос в карантин между разными дисками и при занятом файле.
- Карточку Equipment-EX на своей установке (маркеры сверены по описанию мода в сети, не на игре).
- Доступность моделей по умолчанию (`nvidia/nemotron-3.5-lightning:free`, `google/gemma-4-31b-it:free`) — список взят из `config.example.json`, сеть в тестах замокана.
- Имя правообладателя и год в `LICENSE`.

Известные ограничения, оставленные как есть:

- Отчёты, созданные до S02/S06, со свежим сервером не работают — их надо пересоздать.
- Очистка из дашборда — не больше примерно 2 000 файлов за раз (лимит тела 1 МБ).
- SHA-256 точных копий считается и в предпросмотре, и при применении.
- Карантин, подключённый внутрь Downloads как junction на другой диск, из скана не исключается.
- `.corrupt`-файлы кэшей не удаляются автоматически.
- `start.bat` хранится с переводами строк LF; файла `.gitattributes` нет. После удаления `goto` это менее рискованно, но `*.bat text eol=crlf` стоит добавить.
- GitHub предупреждает, что `actions/checkout@v4` и `actions/setup-python@v5` рассчитаны на устаревший Node.js 20, — обновить версии действий при случае.
- Общей защиты от тестов, читающих пользовательские файлы, нет — только таблица из раздела 3.
