## 1. Инварианты (нарушать нельзя)

- **Только stdlib в рантайме.** Опциональные пакеты подключаются через `try: import`, а при их отсутствии выводится понятное сообщение (так уже сделано с `py7zr`, `rarfile`, `send2trash`). Любую новую зависимость, в том числе dev или CI (ruff, mypy, PyInstaller), добавляй только после согласия Никиты.
- **Reuse First.** Прежде чем писать новое, поищи готовое: `verify_entry`, `_apply_clean_plan`, `_exclusive_file_lock`, атомарную запись из `server.py` / `openrouter_limits.py`, `_is_finite_timestamp` и т. д.
- **Никаких commit / push / release без явной просьбы Никиты.** Готовь изменения и сообщай о них.
- **Файлы пользователя:**
  - по умолчанию ничего не удаляется безвозвратно;
  - любая файловая операция проходит через цепочку *пробный запуск → подтверждение → карантин*;
  - архивы из Vortex и файлы в папке игры никогда не становятся кандидатами на очистку;
  - писать в папку игры и в данные Vortex запрещено, оттуда можно только читать.
- **ИИ только подсказывает.** Mod ID от ИИ не участвует в группировке и чёрном списке, пока не проверен (задача N03).
- **Приватность.** Во внешние сервисы не уходят локальные пути, имя пользователя Windows и сами архивы. Каждый новый внешний запрос включается только флагом или настройкой (opt-in) и описывается в разделе README «Что отправляется внешним сервисам».
- **Сервер** слушает только `127.0.0.1`.
- **Не открывай и не меняй** пользовательские `config.json`, `*_cache.json`, `blacklist.json`, `openrouter_usage.json`. Тесты работают только во временных каталогах.
- **Основная платформа — Windows:** пути с кириллицей и пробелами, длинные пути, архивы на разных дисках, UTF-8. Код под Windows (`winreg`, `ctypes`, `explorer`) прячь за функциями, которые можно замокать в тестах.
- **Крупные изменения** (этапы 2–5, разбиение на пакет) перед слиянием сопровождай кратким описанием диффа и рисков: Никита отдаёт их на независимое ревью второму ИИ.

## 3. Этап 1 — надёжность и безопасность (v1.3.0). Делать первым

### S01. Галочки выбора в дашборде ничего не значат · P0 · S
**Где:** `render_file_item` (`nexus_links.py` ~1500) рисует `<input class="sel" data-fid>` (точные копии отмечены, старые версии нет). JS в `dashboard_template.html` (~842–933) берёт файлы для удаления, BAT и экспорта JSON фильтром `fileData.filter(по verdict)` и на галочки не смотрит. В результате «Экспорт JSON для clean» всегда выгружает **все** точные копии и **все** старые версии, хотя README обещает выгрузить выбранные.
**Сделать:** хранить выбор в `Set` по `data-fid`; экспортировать и чистить только отмеченное; сделать счётчики «выбрано N (X ГБ)», а также кнопки «Выбрать все копии», «Выбрать все старые» и «Снять выбор»; если ничего не выбрано, кнопки неактивны.
**Готово, когда:** снятая галочка не попадает в `selection.json`; по умолчанию выбраны только точные копии, как сейчас визуально.

### S02. Безвозвратное удаление в обход безопасной очистки · P0 · M
**Где:**
- кнопка «🗑 Удалить дубликаты с диска» → `/api/delete` → `os.remove` (`server.py` ~218–231). Нет повторной проверки SHA-256, нет проверки «остающейся» копии, нет карантина, нет проверки расширения: можно удалить **любой** файл внутри Downloads, включая содержимое карантина;
- «Скачать BAT-скрипт» генерирует `del /f /q` без каких-либо проверок;
- если `config.json` отсутствует, сервер считает Downloads папкой `~/Downloads` (`resolve_paths`).

Всё это противоречит разделу README «Безопасная очистка».
**Сделать:**
1. Убрать `/api/delete` (возвращать `410 gone`) и кнопку прямого удаления.
2. Добавить `POST /api/clean/preview` и `POST /api/clean/apply`. Оба принимают тот же формат, что и `selection.json`, и **переиспользуют** `verify_entry` и `_apply_clean_plan` из ядра. Пути сервер берёт из того же `load_settings`, а не из своей копии логики.
3. В UI: «🧹 Перенести выбранное в карантин» → модальное окно предпросмотра (OK / пропуск с причиной, итоговый размер) → «Применить».
4. BAT-экспорт удалить. Экспорт JSON для CLI оставить.
5. Обновить README (разделы «Безопасная очистка» и «Устранение неполадок»).

**Готово, когда:** в `server.py` и JS нет ни одного пути к `os.remove` / `del`. Тесты проверяют, что предпросмотр не меняет файловую систему, apply переносит файлы в карантин, файл с изменённым размером или mtime пропускается, файл вне Downloads отклоняется. Без `config.json` сервер отказывает в очистке, а не берёт `~/Downloads`.
**Зависит от:** S01. Это решение нужно подтвердить у Никиты (вопрос 2), но сама реализация уже понятна.

### S03. Неверные подписи «диск C: / D:» и текст баннера · P1 · S
**Где:** `dashboard_template.html` ~473–475, 493–495, 512–513, а также JS-строка «на диске C:» (~623). Буквы дисков зашиты, хотя могут быть любыми. Баннер утверждает, что «копии уже присутствуют в Vortex (диск D:)», но у точной копии «остающийся» файл может лежать и в Downloads (`_mark_duplicate_cluster`).

**Готово, когда:** есть тест с пользовательским `quarantine = <downloads>/my_q`.

### S05. Неатомарная запись кэшей · P0 · S
**Где:** `save_ai_cache` (`nexus_links.py` ~1161), `_save_cache` и `_save_analysis_cache` (`mod_recommendations.py` ~210, ~470) пишут через `path.write_text`. Если процесс прервётся посреди записи, JSON будет повреждён. Загрузчик тогда молча вернёт `{}`, и следующее сохранение затрёт все накопленные результаты ИИ, то есть потраченную квоту.
**Сделать:** одна общая функция `atomic_write_json(path, data)` (временный файл в той же папке, затем `os.replace`; образец есть в `server.py`). Повреждённый кэш при загрузке переименовывать в `*.corrupt-<дата>.json`, а не перезаписывать.
**Готово, когда:** все записи JSON идут через одну функцию; есть тест «повреждённый кэш сохраняется как `.corrupt`, новые данные пишутся отдельно».

### S06. Укрепить локальный сервер · P0 · M
**Где:** `server.py`.
- `/api/reveal` открывает в Проводнике **любой** существующий путь.
- Проверка `Origin` пропускает запросы вообще без этого заголовка.
- Тело разбирается как JSON при любом `Content-Type`, поэтому `text/plain` из HTML-формы на чужом сайте проходит как «простой» запрос без preflight.
- Заголовок `Host` не проверяется (DNS rebinding).
- `Content-Length` читается без ограничения размера.

**Сделать:**
1. Требовать `Host` ∈ {`localhost:PORT`, `127.0.0.1:PORT`}.
2. Для POST требовать `Content-Type: application/json`, иначе 415.
3. Требовать `Origin` из списка разрешённых либо `Sec-Fetch-Site: same-origin`; если нет обоих — 403.
4. Токен на запуск: `secrets.token_urlsafe()` подставляется в HTML **при отдаче** (`<meta name="api-token">`), JS шлёт его в `X-ModAudit-Token`.
5. Ограничить тело запроса 1 МБ.
6. `/api/reveal` разрешать только внутри downloads, vortex, game и quarantine; для файла использовать `explorer /select,<файл>`, чтобы файл подсвечивался.
7. На `OPTIONS` отвечать явным 405.

**Готово, когда:** на каждый пункт есть тест в `tests/test_server.py`.

**Готово, когда:** повторный скан неизменной папки не вызывает `sha256_file` (тест с подсчётом вызовов через mock), а `start.bat` больше не содержит цикла.

## 4. Этап 2 — точная идентификация модов через Nexus (v1.4.0)

Главная боль проекта в том, что Mod ID угадывается по имени файла (File ID путается с Mod ID, русские названия) или через ИИ. Этап 2 заменяет угадывание детерминированной проверкой.

### R01. Разделить `nexus_links.py` на пакет (подготовка) · P1 · L
Без изменения поведения. Несколько коммитов, после каждого тесты зелёные.
```
modaudit/
  names.py      ParsedName, extract_mod_meta, version_key, compare_freshness
  scan.py       Archive, scan_folder, хеши, папка игры, поиск Steam
  analysis.py   дубликаты, версии, ModRow, build_rows, чёрный список
  ai.py         клиент OpenRouter, промпты, ai_cache
  nexus.py      (из mod_recommendations.py) + NexusClient из N01
  limits.py     (из openrouter_limits.py)
  sources.py    (из mod_categories.py)
  render.py     HTML
  clean.py      clean / verify / quarantine
  config.py     Settings, load_settings, константы
  cli.py        argparse, main
```
`nexus_links.py`, `openrouter_limits.py`, `mod_recommendations.py` и `mod_categories.py` остаются тонкими обёртками с реэкспортом: старые команды из README и `start.bat` должны работать как раньше. Глобальное изменяемое состояние (`MAX_MOD_ID`, счётчики в `limits`) передаётся через объект контекста.

### N01. Единый `NexusClient` и необязательный личный API-ключ · P1 · M
- Все HTTP-запросы к Nexus идут через один модуль: таймауты, `User-Agent` с версией, разбор заголовков лимитов (`x-rl-daily-remaining`, `x-rl-hourly-remaining`), корректная остановка у порога, единый кэш с TTL по типу данных, атомарная запись.
- Ключ берётся из `nexus.api_key` в `config.json` или из `NEXUS_API_KEY` (переменная среды важнее, как у OpenRouter).
- Два бэкенда: REST **v1** с ключом и текущий публичный эндпоинт без ключа (в README помечен как экспериментальный).
- Перед публичным релизом сверить правила Nexus для сторонних приложений: регистрация приложения, атрибуция, лимиты (вопрос 3).

### N02. Идентификация архива по MD5 · P0 для ценности · M
- Флаг `scan --nexus-identify` (нужен ключ). MD5 считается **в том же проходе**, что и SHA-256 (одно чтение, два хешера), и хранится в кэше из S07. MD5 нужен для **всех** архивов без подтверждённого ID; с `--nexus-identify-all` — вообще для всех.
- Запрос `GET /v1/games/cyberpunk2077/mods/md5_search/{md5}.json`. Ответ даёт мод, файл, версию, категорию файла и время загрузки. Точную схему ответа сверь с документацией API.
- Кэш: положительный результат храним бессрочно (MD5 → файл не меняется), 404 — с TTL 30 дней.
- Подтверждённый ID важнее разбора имени и ИИ. В `grouping_reason` пишется «MD5 совпал с файлом на Nexus».
- В `mark_versions` предпочитать время загрузки из Nexus, а не версию из имени файла.
- В README в «Что отправляется внешним сервисам» добавить: уходит только хеш файла.

**Готово, когда:** тесты на замоканных ответах показывают, что переименованный русский архив получает верный ID и объединяется со своими версиями; 404 оставляет архив нераспознанным; при 429 работа останавливается, а кэш сохраняется; лимиты соблюдаются.

### N03. Проверка ID, предложенных ИИ · P1 · S
- Для `AIInfo.mod_id` и для групп с `rejected_id` получить название мода через `NexusClient` (из кэша) и сравнить с `clean_title` от ИИ или названием из файла: нормализованные токены плюс `difflib.SequenceMatcher` (stdlib). Порог — константа.
- Статусы: `confirmed`, `mismatch`, `unavailable`. Только `confirmed` становится `mod_id` группы («ID ИИ подтверждён по названию на Nexus»). `mismatch` явно показывается в UI.
- Работает и без ключа, на текущем публичном эндпоинте.

**Готово, когда:** есть тесты на пример «Виртуальная мастерская» → Virtual Atelier и на случай несовпадения.

### N04. Проверка обновлений · P1 · M
- Для модов с подтверждённым ID и известным file_id запросить `GET /v1/games/cyberpunk2077/mods/{id}/files.json` (кэш 24 ч) и определить, новейший ли у пользователя файл в своей линейке и категории.
- Для экономии квоты сначала запросить `mods/updated.json?period=1w|1m` и спрашивать файлы только у недавно обновлённых модов.
- Новый статус и фильтр «⬆ Есть обновление на Nexus» со ссылкой на `?tab=files`. Файлы, которые Nexus перевёл в старые или архивные, помечаются.
- Ничего не скачивать (см. «Вне рамок»).

### G03. Проверка зависимостей без сети · P1 · S

| Признак в архиве или игре | Нужен |

### G05. Подозрительное содержимое архивов · P2 · S

### G06. Версии игры и фреймворков · P2 · S

### G07. «Доктор логов» · P1 · M

## 6. Этап 4 — дашборд 2.0 (v1.6.0)

### U01. Рендер из данных вместо HTML в f-строках · P1 · L
- Python отдаёт один JSON (строки, файлы, ИИ, Nexus, игра, мета) в `<script type="application/json">`. JS строит DOM через `createElement` / `textContent` (без `innerHTML` для данных), и XSS исключается самой конструкцией.
- Inline-стили уходят из `render_*` в CSS шаблона.
- Выполнять по шагам. Тесты проверяют JSON-полезную нагрузку; визуальную проверку подтвердить скриншотом для Никиты.

### U02. Живые действия через сервер · P1 · M
- `POST /api/scan`: фоновый поток, одновременно только один скан (lock).

- `GET /api/data`: свежие данные без перегенерации страницы.

### U03. Восстановление из карантина · P1 · S

- `quarantine list`.
- `quarantine purge --older-than 30 --apply`: в Корзину через `send2trash`; безвозвратно — только с явным `--permanent`.
- В дашборде — список запусков карантина с кнопкой «Восстановить».

### U04. Скрытие и заметки · P2 · S

- Скрытые группы по умолчанию не видны в фильтрах копий, старых версий и обновлений; есть переключатель «Показать скрытые».

- Свои модальные окна вместо `prompt`, `confirm` и `alert`.

## 12. Стратегическое направление (принято за основу 2026-11-16)

- **Продукт.** Бесплатный open-source «доктор» для коллекции модов. Работает рядом с Vortex и Nexus Mods App и не заменяет их. Не превращать проект в менеджер модов.
- **Монетизация.** Никаких платных функций, подписок и платного доступа: этого не допускают правила фан-контента CDPR, а для публичного приложения нужна регистрация в Nexus по правилам их API. Допустимы только добровольные донаты и Donation Points на Nexus. Ключи пользователей нельзя хранить на своём сервере, поэтому облачного бэкенда с Nexus не будет.
- **ИИ.** Только ключ самого пользователя или бесплатные модели. Своего ИИ-прокси нет.
- **Технологии: развитие, а не переписывание.** Python и проверенная логика остаются. После этапа 1 — разбиение на пакет (R01), затем D01, затем новый интерфейс (U01).
- **D01. Хранилище на SQLite · P1 · M.** Один файл `modaudit.db` (`sqlite3` из stdlib) вместо JSON-кэшей: хеши, ИИ, Nexus, состояние пользователя, снимки. Транзакции заменяют самописные блокировки и атомарную запись. Схема версионируется (`PRAGMA user_version`, миграции). Есть одноразовый импорт старых JSON с сохранением оригиналов. Файлы `blacklist.json` и `config.json` остаются JSON, их пользователь редактирует руками.
- **Интерфейс (U01–U06).** Разделы:
  - «Обзор» — что сделать в первую очередь;
  - «Библиотека»;
  - «Очистка» — мастер «выбрать → проверить → в карантин»;
  - «Игра» — установленное, зависимости, логи;
  - «Настройки» — вместо ручной правки `config.json`.

  Тёмная тема со спокойным неоном, эффекты можно выключить. Название и брендинг — вопрос 8, окно вместо браузера — вопрос 9.
